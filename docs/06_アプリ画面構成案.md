# Webアプリ 画面構成案(承認待ち)

作成日: 2026-09-18
前提(2026-09-17 ご回答): MySQL / PHP + HTML + CSS + JavaScript(フレームワークなし) / XServer に FFFTP でアップロード / ログイン利用者 10人程度 / PC のみ

## 技術方針

| 項目 | 方針 | 理由 |
|---|---|---|
| PHP | 8.x、素の PHP(Composer・フレームワーク不使用) | FFFTP でファイルを置くだけで動かすため |
| DB接続 | PDO(pdo_mysql)、プリペアドステートメント | SQLインジェクション対策 |
| 構成 | `public/` 配下を公開ディレクトリに置く。`app/`(設定・共通処理)は公開ディレクトリの外 | DB接続情報を外部から読めないようにする |
| 画面 | サーバー側で HTML を生成。JavaScript は入力補助(絞り込み・確認ダイアログ・一括入力)のみ | PC 専用、シンプルに保つ |
| セッション | PHP 標準セッション。CSRF トークン付き | ログイン保護 |
| パスワード | password_hash / password_verify(bcrypt) | 平文保存しない |
| 初期設定 | `public/setup.php` を1回だけ実行して管理者を作成し、その後ファイルを削除 | 初期パスワードをコードに埋め込まない |
| 文字コード | UTF-8 / utf8mb4 | 全角文字・記号のため |

## 確認したい点

| # | 内容 | 私の案 |
|---|---|---|
| S-01 | 「棚卸の確定」は誰でもできてよいか、管理者のみか | 管理者のみ |
| S-02 | 品目の「無効化」(削除の代わり)は誰でもできてよいか | 全員可、ただし棚卸履歴がある品目は物理削除不可(無効化のみ) |
| S-03 | 棚卸入力で「前回棚卸数」は直前の確定済み棚卸の値でよいか | よい(D-05 のとおり) |
| S-04 | CSV出力の要否(品目一覧・棚卸結果) | 付ける(Excel で開ける UTF-8 BOM付き) |
| S-05 | 「ログイン10人くらい。変更できるならありがたい」の意味 | 「利用者が自分のパスワードを変更できる」+「管理者が利用者を追加・変更できる」と解釈(画面12・13) |
| S-06 | 品目コード(ITEM-000001)の採番 | 自動採番(変更不可)。QR/バーコード印刷は今回対象外 |
| S-07 | 客先マスタの初期登録 | 空のまま。運用開始後に画面から登録(候補: 恵会 / 永和会 / 腎愛会 / エミフル) |

## ディレクトリ構成(案)

```
app/                         ← 公開ディレクトリの外に置く
  config.php                 ← DB接続情報(FFFTPで置く前に書き換え)
  bootstrap.php              ← 共通初期化(セッション・DB・認証)
  lib/                       ← 共通関数(認証、CSRF、表示ヘルパー)
  views/                     ← 画面テンプレート
public/                      ← XServer の公開ディレクトリ(public_html/棚卸/ など)に置く
  index.php                  ← ルーティング(?page=items など)
  setup.php                  ← 初回のみ: 管理者作成(実行後に削除)
  assets/style.css, app.js
sql/
  001_schema.sql             ← テーブル作成
  002_seed_master.sql        ← マスタ初期データ
  003_migrate_excel.sql      ← Excel移行データ
```
